# Mission Planning and Execution

A mission is a **predefined flight plan**: planned in QGroundControl, uploaded to the flight controller, then flown autonomously in **Mission mode**. Typical contents include takeoff, flying through a sequence of waypoints, taking photos or video, dropping a payload, and landing.

This is the most mature path to autonomous flight in the PX4 ecosystem, and it needs no programming — **if a mission can do the job, don't use offboard**; stability and failsafe support are far better.

## Planning in QGC

Manual planning is straightforward: switch to the mission view → **Add Waypoint** (the plus icon, top left) → click waypoints on the map → edit waypoint parameters and types in the list on the right (the altitude indicator at the bottom shows each waypoint's relative altitude) → **Upload** (top right) to send it to the vehicle.

For more advanced plans, the **Pattern** tools generate survey grids automatically; QGC offers several patterns (see [[raw/documents/QGC/plan_view/pattern]]):

| Pattern | Use |
| --- | --- |
| Survey | Mapping a ground area |
| Corridor Scan | Mapping corridors (roads, pipelines, riverbanks) |
| Structure Scan | Scanning vertical structures |
| Fixed Wing Landing | Fixed-wing landing pattern |

The mission, the geofence ([[wiki/concepts/geofence]]) and rally points are **three parts of the same Plan**, uploaded together.

## Feasibility checks (things that will stop you taking off)

PX4 runs basic sanity checks on missions — for example, whether the mission is close enough to the vehicle, whether it conflicts with the geofence, or whether a required mission landing pattern is missing.

**The checks run once at upload and again before execution; if any check fails, the user is notified and the mission cannot be started.** The details differ per vehicle type and are documented separately in the multicopter and fixed-wing Mission mode pages.

## Default heading behaviour (easy to misunderstand)

- If the target waypoint explicitly sets a **Heading** (`MAV_CMD_NAV_WAYPOINT.param4`), a multicopter turns to that heading
- **If not (`param4=NaN`), the `MPC_YAW_MODE` parameter decides**, and the default is to face the next waypoint

When the camera points the wrong way during a photo mission, this is usually why — no Heading was set, so the default applied.

## Programmatic access

MAVSDK provides two plugins, and **the choice matters**:

| Plugin | Characteristics |
| --- | --- |
| `Mission` | High-level abstraction with a simplified mission item model; easy to write |
| `MissionRaw` | Works directly with MAVLink mission items; **can represent the full missions that QGC plans** (including complex items generated by patterns) |

Use `MissionRaw` ([[raw/documents/MAVSDK/plugins/mission_raw]]) when you need to upload or download `.plan` files produced by QGC, or when you need mission commands the high-level abstraction does not support.
